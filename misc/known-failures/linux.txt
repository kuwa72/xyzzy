# ウィンドウの分割と構成、エコー領域 — **この群は空になった。**
#
# ここには 27 件が並んでいて、「`--batch` には画面が無いから仕方ない」と
# 書いてあった。**それが間違いだった。** 原因は画面の有無ではなく、
# `compute_geometry` が `getmaxyx (stdscr, ...)` を直に呼んでいたことである。
# `--batch` では curses を上げないので `stdscr` が 0 で、`getmaxyx` は
# rows も cols も -1 にする。それで `app.active_frame.size` が毎回 -1 に
# 上書きされ、`create_batch_windows` が置いていた 80x24 が消えていた。
# その結果すべてのウィンドウの矩形が潰れ、`split-window` は「分割できません」、
# `window-height` は 1、`screen-height` は -1 を返していた。
#
# **画面が無いのは正しいが、大きさが無いのは正しくない。** 端末の大きさを
# 取る所を 1 箇所 (`term_size`) にまとめ、curses が上がっていなければ
# フレームの持っている大きさを使うようにしたら 23 件が通った。
#
# 残った 4 件のうち 3 件は `window-lines` の別のバグだった: モード行の
# 1 行を一律に引いていて、**モード行を持たないミニバッファでも引いていた。**
# 残り 1 件は `*current-pseudo-frame*` が nil のときの `pseudo-frame-name`。
# どちらも「バッチだから」ではなく、ただのバグだった。
#
# **教訓として残す: 「環境の制約」と書いてある既知失敗は疑う価値がある。**
# 27 件のうち 27 件が環境ではなく実装の問題だった。
