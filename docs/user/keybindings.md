キーバインド
============

xyzzy は Emacs 風のキー操作です。多くのコマンドがモードごと・機能ごとに
別々のファイルでキーに割り当てられていて、単一の「デフォルトキーマップ」
という一覧表は xyzzy 自身の中にもありません。**実際に効いている全キー割り当ては
メニューの「ヘルプ」→「キー割り当て一覧」でいつでも確認できます** (現在の
バッファのモードで有効なものも含めて出ます)。ここでは最初に覚えると楽なものと、
見落としがちなものを挙げます。

ここに載っているのは `~/.xyzzy` などで何もカスタマイズしていない、素の
xyzzy のデフォルト状態です。`lisp/Gates.l` や `lisp/winkey.l` (Windows 風
キーバインドのサンプル) は同梱されてはいますが `require` しない限り効かない
ので対象外にしています。

Leader Key (モダン操作体系 & Which-key ガイダンス)
-------------------------------------------------

`M-m` または `C-c SPC` を押すと、画面を分割した `*Which Key*` ウィンドウに
利用可能な機能カテゴリが段組みで一覧表示され、キーボードだけで迷わず目的の
コマンドを実行できます (`lisp/leader.l`)。

```
 [Leader]
 b  Buffer+   f  File+     h  Help+     s  Search+   w  Window+   /  Grep      v  Expand
 c  Code+     g  Git+      p  Project+  t  Toggle+   SPC  M-x     V  Contract
```

`+` の付いた項目はサブメニューです。もう 1 打鍵すると
`[Leader > Window]` のように中身が出ます。選ぶと一覧は閉じ、元のウィンドウ
構成に戻ってからコマンドが走ります。`C-g` / `ESC` で取り消し。

| キー | カテゴリ / 動作 | 主要サブコマンド |
|---|---|---|
| `M-m` / `C-c SPC` | Leader メニュー起動 | ミニバッファに Which-key ガイダンスを表示 |
| `Leader f` | **File** | `f`: 開く, `r`: 最近のファイル, `s`: 保存, `w`: 別名保存, `d`: ファイラ |
| `Leader b` | **Buffer** | `b`: 切り替え, `k`: 閉じる, `l`: バッファ一覧, `r`: 再読込, `n`/`p`: 次/前 |
| `Leader p` | **Project** | `f`: ファイル検索, `g`: プロジェクトGrep, `d`: ルートファイラ, `t`: ターミナル, `p`: プロジェクト切替 |
| `Leader s` | **Search** | `s`/`r`: 検索, `g`: Grep, `q`: 置換 |
| `Leader g` | **Git** | `s`: ステータス, `d`: 差分, `l`: ログ, `b`: Blame |
| `Leader t` | **Toggle / Tools** | `t`: ターミナルドロワー, `l`: 行番号, `w`: 折り返し, `c`: 電卓, `p`: 自動ペア挿入, `T`: ダーク/ライト切り替え, `C`: カラーテーマ選択, `m`: モード行の切り替え |
| `Leader w` | **Window** | `s`: 上下分割, `v`: 左右分割, `o`: 隣へ移動, `d`: 閉じる, `m`: 最大化, `u`/`r`: レイアウトを戻す/やり直す |
| `Leader o` | **Open / Notes** | `s`: `*scratch*` へ跳ぶ, `m`: その日のメモを開いて追記, `M`: メモの置き場をファイラで開く |
| `Leader c` | **Code** | `s`: シンボル一覧へジャンプ (`imenu`), `i`: 定型コードを一覧から挿入, `e`: 略語を定型コードに展開, `f`: 関数一覧ダイアログ (`list-function`) |
| `Leader h` | **Help** | `k`: キー説明, `f`: 関数説明, `v`: 変数説明, `b`: 一覧, `a`: Apropos |
| `Leader SPC` | `M-x` | コマンド名をファジー絞り込みで選んで実行 (`fuzzy-execute-extended-command`) |
| `Leader /` | `Grep` | Grep 検索 |

`C-x` や `C-c` を押したときも、次に何が打てるかがステータス行に出ます。

```
[C-x] C-k  Kanji+  4  OtherWin+  6  Frame+  r  Register+  C-a  add-mode-abbrev  C-b  List  +57
```

`+` の付いたものはさらに次のキーがあるプレフィックスで、`+57` は「あと 57 個
あって 1 行に入らなかった」という意味です。`C-x 4` のように絞られていけば全部
出ます。`M-x toggle-which-key-prefix` でオン/オフ。

`M-m` (Leader) の候補一覧が分割ウィンドウに段組みで出るのに対し、こちらは
ステータス行 1 行です。**`C-x` は日常の打鍵なので、待っている間だけ画面の
レイアウトが変わるのを避けています。**

`M-x` (`Leader SPC` も同じ)、`Leader p f` (プロジェクト内ファイル検索)、
`Leader p p` (プロジェクト切替) は、入力するそばから部分一致でファジー
絞り込みするミニバッファ (`lisp/fuzzy-complete.l`) を使います。通常の
`completing-read` と違い、文字を打った順番どおりに含まれていれば
(連続していなくても) 候補に残ります。

**空白で区切って複数のキーワードを打つと、順不同でどれも含むものに
絞られます** (`buf list` で `list-buffers`、`find file` で `find-file`)。

候補は画面を分割した `*Candidates*` ウィンドウに 1 行 1 件で縦に並びます。
1 行目に打ちかけのクエリと件数、選択中の候補の行頭に `>` が付きます。
`M-x` では **右端にそのコマンドの割り当てキー**が出ます (Marginalia 相当。
複数あるときは一番短いもの)。`imenu` では行番号が出ます。

```
 M-x buf    -- 1/67 件 --
 > save-buffer                                                        C-x C-s
   next-buffer                                                           Home
   kill-buffer                                                          C-x k
   eval-buffer
   list-buffers                                                       C-x C-b
   select-buffer                                                           F2
   ...
```

選び終わると (`RET` でも `C-g` でも) ウィンドウ構成は元に戻ります。
`*fuzzy-vertical*` を nil にすると、従来のステータス行 1 行に幅の許すだけ
並べる表示になります (選択中のものは `[...]` で囲まれ、入り切らなかった側に
`…` が付く)。行数は `*fuzzy-vertical-lines*` で変えられます。

| キー | 動作 |
|---|---|
| 文字入力 | クエリに追加してその場で絞り込み直す |
| `C-h` / `DEL` / `Delete` | クエリの末尾を1文字削除 |
| `C-u` | クエリを全消去 |
| `C-n` / `↓` / `TAB` | 絞り込み結果内で選択を1件進める |
| `C-p` / `↑` | 選択を1件戻す |
| `RET` | 選択中の候補を確定 |
| `C-g` | キャンセル |

M-x とミニバッファ
------------------

`M-x` や `C-x C-f` などでコマンド名・ファイル名を入力する下部の 1 行 (ミニバッ
ファ) にいるときの操作です (`lisp/minibuf.l`)。

| キー | 動作 |
|---|---|
| `RET` | 確定して実行 |
| `TAB` | 補完 |
| `SPC` | 単語単位で補完 (ファイル名補完などで) |
| `C-g` | 入力を中断してキャンセル |
| `ESC ESC` | 入力を中断してキャンセル |
| `C-p` / `↑` | 1 つ前の入力履歴を呼び出す |
| `C-n` / `↓` | 1 つ後の入力履歴を呼び出す |
| `M-p` | 1 つ前の入力履歴を呼び出す (`C-p` と同じ) |
| `M-n` | 1 つ後の入力履歴を呼び出す (`C-n` と同じ) |

ミニバッファの中では `C-p`/`C-n` が「1 行上/下へ移動」ではなく「履歴を辿る」に
上書きされている点に注意してください (1 行しかないので移動先が無いため)。文字
単位の移動 (`C-f`/`C-b`/`C-a`/`C-e` など) は通常のバッファと同じです。

基本の移動・編集
----------------

| キー | 動作 |
|---|---|
| `C-f` / `→` | 1 文字進む |
| `C-b` / `←` | 1 文字戻る |
| `C-n` / `↓` | 1 行下へ |
| `C-p` / `↑` | 1 行上へ |
| `C-a` | 行頭へ |
| `C-e` | 行末へ |
| `C-v` / `PageDown` | 1 画面下へスクロール |
| `M-v` / `PageUp` | 1 画面上へスクロール |
| `C-Down` | 1 行だけ下へスクロール (高速スクロール) |
| `C-Up` | 1 行だけ上へスクロール (高速スクロール) |
| `S-C-Down` | 分割した両方のウィンドウを同時に下へスクロール |
| `S-C-Up` | 分割した両方のウィンドウを同時に上へスクロール |
| `C-l` | カーソル行が画面中央に来るよう再描画 (recenter) |
| `C-x <` | 画面を左へスクロール |
| `C-x >` | 画面を右へスクロール |
| `ESC C-v` | 隣のウィンドウをスクロール (自分のカーソルは動かさない) |
| `C-d` / `Delete` | カーソル位置の 1 文字を削除 |
| `DEL` / `BS` | カーソルの前の 1 文字を削除 |
| `C-k` | カーソル位置から行末まで削除 (kill) |
| `C-y` | 直前に kill した内容を貼り付け (yank) |
| `C-SPC` / `C-@` | マークをセット (リージョンの起点) |
| `C-w` | リージョンを切り取り |
| `M-w` | リージョンをコピー |
| `C-t` | カーソル前後の 2 文字を入れ替え |
| `C-x C-x` | カーソル位置とマークを入れ替え |
| `Insert` | 上書きモードの切り替え |
| `M-↑` | 現在行 (選択中なら選択範囲の行) を 1 行上へ移動 |
| `M-↓` | 現在行 (選択中なら選択範囲の行) を 1 行下へ移動 |
| `C-=` | 選択範囲を意味のある単位で 1 段階広げる |
| `M-=` | 広げた分を 1 段階戻す |

`M-↑`/`M-↓` (`lisp/move-text.l`) は kill-ring を汚さず、選択範囲も移動先へ
張り直します。`C-k` して `C-y` するのと違って、貼り付け直す前に別の kill を
挟んでしまう事故がありません。

括弧・引用符の自動ペア挿入
--------------------------

`(`, `[`, `{`, `"` を打つと閉じ側も一緒に入り、カーソルはその間に来ます
(`lisp/autopair.l`)。閉じ側を自分で打っても重ならず、既にある閉じ文字を
乗り越えるだけです。`M-x toggle-autopair` (`Leader t p`) でオン/オフ。

| 打鍵 | 結果 (`|` はカーソル位置) |
|---|---|
| `(` | `(|)` |
| `(` を `foo` の直前で | `(|foo` (対にしない) |
| `)` が既にある位置で `)` | 重ねずに乗り越えるだけ |
| `BS` を `(|)` で | `()` の 2 文字がまとめて消える |
| 選択したまま `(` | 選択範囲を `(...)` で囲む (置き換えない) |

余計なことをしないほうへ倒してあり、次の場合は対にしません。

  * 語や記号の直前 (既にあるテキストを括弧で挟んでしまわないように)
  * 文字列・コメントの中
  * `\` の直後
  * 繰り返し引数付き (`C-u 3 (` など)・上書きモード・キーボードマクロ実行中
  * ミニバッファの中 (`*autopair-in-minibuffer*` を non-nil にすると有効)

`'` と `` ` `` は既定では対になりません。Lisp ではこの 2 つは対ではなく
クォート (前置演算子) で、xyzzy の設定ファイル自身が Lisp なので、対にすると
邪魔になる場面のほうが多いためです。必要なら `*autopair-pairs*` に足します。

選択範囲の段階的拡大
--------------------

`C-=` / `M-=` (`lisp/expand-region.l`、`Leader v` / `Leader V` でも同じ) は
押すたびに

    単語 → シンボル → 引用符の中 → 引用符ごと → 括弧の中 → 括弧ごと
    → (外側の括弧へ、以下同様) → 行 → 関数定義 → バッファ全体

と選択範囲を広げます。成立しない段階 (Lisp でない所の関数定義など) は
自動的に飛ばされます。途中でカーソルを動かすと数え直しになります。

検索・置換
----------

デフォルトの `C-s` / `C-r` はインクリメンタルではない (パターンを打って `RET` で
確定する) 検索です。打鍵ごとに絞り込む isearch は `lisp/isearch.l` にあります
が起動時のロード対象 (`lisp/loadup.l`) に入っておらず、デフォルトでは読み込まれ
ません。isearch にしたい場合は `~/.xyzzy` に以下を書いてください。

```lisp
(require "isearch")
```

`isearch.l` がロード時に `C-s` / `C-r` を isearch-forward / isearch-backward
に上書きします。

| キー | 動作 |
|---|---|
| `C-s` | 検索 (前方、パターンを入力して `RET`) |
| `C-r` | 検索 (後方) |
| `M-s` | 正規表現検索 (前方) |
| `M-C-s` | 正規表現検索 (後方) |
| `M-r` | 文字列を置換 |
| `C-M-r` | 問い合わせ置換 |

`C-M-r` (問い合わせ置換) を実行すると、1 件ごとに置換するか聞かれます。この
とき押すキーは通常の編集キーとは別物です:

| キー | 動作 |
|---|---|
| `SPC` / `y` | この箇所を置換して次へ |
| `n` / `C-d` / `Delete` / `C-h` | この箇所はスキップして次へ |
| `!` | 残り全部を確認なしで置換 |
| `.` | 中止して、コマンドを始めた位置に戻る |
| `ESC` / `q` / `C-g` | 中止 (現在位置に留まる) |
| `^` / `u` | 直前の置換を元に戻す |
| `C-l` | 画面を再描画 |

レジスタ
--------

位置・文字列・矩形・ウィンドウ構成を名前 (1 文字) を付けて保存できる機能です
(`lisp/register.l`)。`C-x r` の後にもう 1 打鍵します。

| キー | 動作 |
|---|---|
| `C-x r SPC` | 現在位置をレジスタに保存 |
| `C-x r j` | レジスタに保存した位置へジャンプ |
| `C-x r s` / `C-x r x` | リージョンをレジスタにコピー (同じ動作) |
| `C-x r i` / `C-x r g` | レジスタの内容を挿入 (同じ動作) |
| `C-x r a` | リージョンをレジスタに追記 |
| `C-x r r` | 矩形リージョンをレジスタにコピー |
| `C-x r w` | 現在のウィンドウ構成をレジスタに保存 |
| `C-x r c` | レジスタからウィンドウ構成を復元 |

キーボードマクロ
----------------

操作列を記録して繰り返し実行する機能です (`lisp/kbdmacro.l`)。

| キー | 動作 |
|---|---|
| `C-x (` | 記録を開始 |
| `C-x )` | 記録を終了 |
| `C-x e` | 最後に記録したマクロを実行 |

ページ (フォームフィード区切り)
--------------------------------

xyzzy 内部では「ページ」という言葉が 2 つの別の意味で使われています。
`C-v`/`M-v`/`PageUp`/`PageDown` (前述の「基本の移動・編集」) は
コマンド名こそ `next-page`/`previous-page` ですが実体は画面スクロールです。
一方こちらは `^L` (フォームフィード) で区切った「ページ」の間を移動する、別の
機能です (`lisp/page.l`)。

| キー | 動作 |
|---|---|
| `C-x [` | 前のページ区切りへ |
| `C-x ]` | 次のページ区切りへ |
| `C-x C-p` | カーソルを含むページ全体をマーク |

C-c プレフィックス (IME・辞書・サブプロセス・ファイラ)
--------------------------------------------------------

`C-c` はグローバルなプレフィックスキーです (`lisp/cmds.l` で
`specific-command-prefix` に割り当て)。以下の機能がここにまとめて登録されて
います。文字コード/IME 関連 (`lisp/kanji.l`)、サブプロセス終了
(`lisp/process.l`)、ファイラ (`lisp/filer.l`)、辞書引き (`lisp/edict.l`)。

| キー | 動作 |
|---|---|
| `C-c C-c` | IME の変換を巻き戻して再変換 |
| `C-c C-d` | 直前に確定した IME の文字列を削除 |
| `C-c C-r` | IME 単語登録ダイアログ |
| `C-c C-p` | IME の変換文字列を push |
| `C-c C-k` | 実行中のサブプロセスを強制終了 |
| `C-c C-f` | ファイラを開く |
| `C-c e` | 選択範囲を英和辞書で引く |
| `C-c i` | 選択範囲をイディオム辞書で引く |
| `C-c j` | 選択範囲を和英辞書で引く |
| `C-c r` | 選択範囲の読みを引く |

**注意**: ターミナル/シェルバッファの中では `C-c C-c`/`C-c C-f` がモード固有の
別コマンド (Ctrl-C 送信・ファイルを開く) に上書きされます。詳しくは
[ターミナル](#ターミナル)を参照してください。

文字コード・EOL
----------------

`C-x C-k` の後にもう 1 打鍵します (`lisp/kanji.l`)。Emacs の `C-x C-k` は
キーボードマクロ編集ですが、xyzzy では文字コード関連のプレフィックスです。

| キー | 動作 |
|---|---|
| `C-x C-k f` | 現在のバッファの読み書きエンコーディングを変更 |
| `C-x C-k F` | 新規バッファのデフォルトエンコーディングを変更 |
| `C-x C-k n` | 現在のバッファの改行コードを変更 |
| `C-x C-k N` | デフォルトの改行コードを変更 |
| `C-x C-k c` | クリップボードのエンコーディングを変更 |

補完リスト

ミニバッファの `TAB` 補完で候補が複数あるとき表示される `*Completion*` の
中では `RET` (候補をミニバッファへコピー) だけが特別なキーで、それ以外の

カレンダー
----------

`M-x calendar` で開くカレンダーバッファです (`lisp/calendar.l`、autoload)。

| キー | 動作 |
|---|---|
| `C-v` / `PageDown` | 次のページ (末尾では次の年) へ |
| `M-v` / `C-z` / `PageUp` | 前のページ (先頭では前の年) へ |

ヘルプ・apropos
----------------

`describe-function`/`describe-variable`/`apropos` などが出す `*Help*`
バッファには特別なキーは無く、普通の読み込み専用バッファとして通常のカーソル
移動キーで読みます (閉じるときは `C-x k` など)。

ターミナル
----------

`M-x shell` で開いたターミナルバッファ (詳細は [機能一覧](features.md#ターミナルエミュレータ))
の中で使えるキーです (`lisp/shell.l`)。ここでの `C-c C-c`/`C-c C-f` は前述の
「C-c プレフィックス」の節とは別物のモード固有の割り当てで、ターミナル
バッファの中でのみ有効です。

| キー | 動作 |
|---|---|
| `RET` | 現在の行をプロセスへ送る |
| `C-j` | 現在の行を、逆の改行コードで送る |
| `C-c C-c` | プロセスに Ctrl-C を送る |

フルスクリーンのアプリ (vim・htop など) を動かしている場合はさらに以下も
使えます:

| キー | 動作 |
|---|---|
| `C-v` / `S-Insert` | クリップボードの内容をそのままプロセスへ貼り付け |
| `S-PageUp` / `S-PageDown` | スクロールバック (画面に出ていない過去の出力) を見る |
| `C-c C-c` | フルスクリーンアプリへ Ctrl-C を送る |
| `C-c o` | 他のウィンドウへ移動 (エディタの操作へ一時的に抜ける) |
| `C-c b` | バッファ切り替え |
| `C-c k` | バッファを閉じる |
| `C-c 0` / `C-c 1` / `C-c 2` | ウィンドウを閉じる/1 つにする/分割する |
| `C-c C-f` | ファイルを開く |
| `C-c C-q` | 次に押したキーを 1 回だけそのままアプリへ渡す |

ターミナルバッファのキーは、この表に載っているものだけがエディタ側に取られ、
残りは全部そのままアプリへ流れます。`M-x` や `C-x C-f` もアプリへ行くので、
エディタの操作をしたいときは上の `C-c` から始まる割り当てを使ってください。

逆に、この表に載っているキーをアプリへ渡したいときが `C-c C-q` です。vim の
`C-v` (矩形選択) や less の `S-PageUp` のように、xyzzy 側で意味を持たせて
しまったキーを 1 回だけ素通しします。

マウスは次のとおりです (Windows 版)。

| 操作 | 動作 |
|---|---|
| 左ドラッグ | テキストを選択する。ボタンを離した時点でクリップボードへ入る |
| ホイール | スクロールバック (`S-PageUp` と同じ) |
| スクロールバー | 同上。つまみのドラッグ・矢印・余白クリック |
| クリック | そのウィンドウを選ぶ |

vim・htop・claude code のようにマウスを自分で使うアプリを動かしている間は、
ドラッグもホイールもアプリへ渡ります。そのときでも **Shift を押しながら
ドラッグすればこちら側の選択になります** (実端末と同じ逃げ道)。

選択は画面の桁・行で持っているので、アプリが何か出力した時とスクロール
バックを動かした時は指す文字が変わってしまうため解除されます。貼り付けは
`C-v` / `S-Insert` です。

モードごとのキー
----------------

ファイルの種類 (拡張子) によって自動的に切り替わる、あるいは `M-x <モード名>`
で切り替えるモードごとの追加キーです。ここまでに挙げたグローバルなキーに、
モードごとの追加・上書きが乗ります。

### Lisp (`.l`/`.lisp`)

| キー | 動作 |
|---|---|
| `C-M-x` | カーソルを含むトップレベルの式を評価 |
| `TAB` | Lisp 流にその行をインデント |
| `C-M-q` | 続く S 式全体をインデントし直す |
| `)` | 閉じ括弧を打つと対応する開き括弧を一瞬光らせる |
| `RET` | 改行してインデント |

### C (`.c`) / C++ (`.cc`/`.cxx`/`.cpp`/`.hxx`/`.hpp`)

`.h` は中身を見て C/C++ のどちらのモードか自動判定します。

| キー | 動作 |
|---|---|
| `{` / `:` / `#` | 打った後、文字列・コメント中でなければその行を自動インデント |
| `}` | 打った後に自動インデントし、対応する `{` を一瞬光らせる |
| `TAB` | その行をインデント (タグシステムが有効ならタグ情報を使って計算) |
| `C-M-q` | ブロック全体をインデントし直す |
| `RET` | 行末の余分な空白を削り、改行してインデント |
| `C-c C-t` | (タグシステム) 呼び出し元の一覧を表示 |
| `C-c C-i` | (タグシステム) インデント計算のデバッグ表示 |

Perl (`.pl`/`.pm`/`.cgi`)、Java (`.java`)、JavaScript/TypeScript
(`.js`/`.jsx`/`.ts`/`.tsx`) もほぼ同じ電飾キー (`{`/`}`/`RET`/`TAB` など) を
共有しています。

### text-mode (`.txt`/`.log`)

| キー | 動作 |
|---|---|
| `M-S` | カーソルのある段落を中央寄せ |

### shell-script-mode (`.sh`/`.bash`/`.zsh`)

インデント目的の編集モードで、実行系のキーはありません。

| キー | 動作 |
|---|---|
| `RET` | 改行してインデント |
| `TAB` | その行をインデント |

### Python (`.py`/`.pyw`)

| キー | 動作 |
|---|---|
| `RET` | 改行してインデント |
| `TAB` | その行をインデント |
| `:` | 打った後、ブロックの見出し行として自動インデント |

### Markdown (`.md`/`.markdown`)

| キー | 動作 |
|---|---|
| `C-c C-n` / `C-c C-p` | 次/前の見出しへ |
| `C-c C-u` | 親の見出しへ |
| `C-c C-f` / `C-c C-b` | 見出しを (同じ階層で) 前後へ |
| `C-c C-=` / `C-c C--` | 見出しレベルを上げる/下げる |
| `C-c C-s b` / `C-c C-s i` / `C-c C-s c` | 太字/斜体/コードで囲む |
| `C-c C-l` | リンクを挿入 |
| `C-c C-x` | チェックボックス `[ ]`/`[x]` を切り替え |
| `C-c C-o` | カーソル位置のリンクを開く |
| `M-RET` | 箇条書き/番号付きリスト/チェックボックスを続けて改行 |

### JSON (`.json`/`.jsonc`) / YAML (`.yml`/`.yaml`) / CMake (`.cmake`/CMakeLists.txt) / XML (`.xml` など) / SQL (`.sql`)

いずれも `RET`/`TAB` によるインデント編集が基本です。JSON は `}`/`]` で自動
再インデント、XML は `>` で自動再インデントします。YAML は `C-c C-n`/`C-c C-p`
でセクション (トップレベルのキー) 間を移動できます。SQL だけは `M-TAB` で
キーワード補完という別系統のキーを持ちます。

### Pascal (`.pas`)

| キー | 動作 |
|---|---|
| `}` | 対応する `{` (Pascal のコメント) を光らせる |
| `ESC ]` | 対応する括弧・角括弧・波括弧へジャンプ |

### LaTeX (`.tex`)

| キー | 動作 |
|---|---|
| `ESC TAB` | LaTeX コマンド名を補完 |
| `\` / `$` | 打つ前に IME をオフにしてから入力 (設定時) |

### HTML (`.htm`/`.html`/`.shtml`)

xyzzy のマークアップ系モードの中で最も多機能です。

| キー | 動作 |
|---|---|
| `TAB` | タグ/属性名を補完 |
| `/` | 閉じタグを自動補完 |
| `C-,` | 対応するタグを推測して挿入 |
| `C-.` | 直近の開きタグに対応する閉じタグを挿入 |
| `C-:` | タグの対応をチェック |
| `C-M-f` / `C-M-b` | タグ単位で前後へ移動 (S 式移動と同じ感覚) |
| `C-x C-i` | 画像タグを挿入 |
| `C-x C-m` | リンク挿入ダイアログ |

### view-mode (読み込み専用の閲覧モード)

Emacs の view-mode よりだいぶ簡素です。

| キー | 動作 |
|---|---|
| `SPC` | 次のページへ |
| `C-h` | 前のページへ |

### calc (`M-x calc`)

`$ ` プロンプトの後に式を書いて評価する電卓バッファです。

| キー | 動作 |
|---|---|
| `RET` | 直前の `$` 以降の式を評価し、結果を表示して次の `$ ` を出す |

### box-drawings-mode (`M-x box-drawings-mode` でオン/オフ)

罫線を引くためのマイナーモードです。有効な間、方向キーに Ctrl を組み合わせた
キーが罫線描画に上書きされます。

| キー | 動作 |
|---|---|
| `C-→`/`C-←`/`C-↑`/`C-↓` | その方向へ罫線を引く (既存の線と接続) |
| `C-S-→`/`C-S-←`/`C-S-↑`/`C-S-↓` | その方向の罫線を消す |
| `C-M-→`/`C-M-←`/`C-M-↑`/`C-M-↓` | その方向に矢印を上書き |

以下のモードはシンタックスハイライトのみで特筆すべきキー割り当てが無いため
省略しています: dockerfile-mode、makefile-mode、idl-mode。ゲーム類
(`M-x hanoi`、`M-x life`、`M-x gomoku`) も同様の理由で割愛しています。

Emacs との違いに注意
--------------------

xyzzy は Emacs 風ですが、指が Emacs に馴染んでいる人ほど事故りやすいキーが
いくつかあります。デフォルト状態 (どのファイルも `~/.xyzzy` で上書きしていない
状態) での違いです。

| キー | xyzzy での動作 | Emacs での動作 |
|---|---|---|
| `C-h` | 1 文字削除 (BS と同じ) | ヘルプ |
| `C-\` | undo | (割り当てなし) |
| `C-_` | redo | undo |
| `End` | undo (`F12` も同じ) | 行末へ移動 |
| `S-End` | redo | 選択範囲を行末まで拡張 |
| `Home` | 次のバッファへ切り替え | 行頭へ移動 |
| `C-←` / `C-→` | 行頭 / 行末へ移動 (`C-a`/`C-e` と同じ) | 単語単位で移動 |
| `C-z` | 前ページへスクロール | フレームをサスペンド |
| `ESC SPC` | マークをセット | 空白を 1 個に詰める |
| `ESC /` | 空白を 1 個に詰める | dabbrev-expand |
| `C-x /` | dabbrev-expand | (割り当てなし) |
| `M-r` | 文字列を置換 | ウィンドウ内でカーソル行を移動 |
| `ESC ESC` | 式を評価 (eval-expression) | (割り当てなし。Emacs では `M-:`) |
| `C-x C-v` | 対応するファイルを開く (find-other-file) | 別のファイルを開き直す (find-alternate-file) |
| `C-x C-n` | バッファ名を変更 | ゴール桁を設定 |
| `C-x C-k` | 文字コードを指定して入力 | キーボードマクロ編集 (Emacs 24 以降) |
| `C-x z` | ウィンドウを広げる | 直前のコマンドを繰り返す (Emacs 28 以降) |
| `C-x C-z` | ウィンドウを狭める | フレームをサスペンド |
| `C-x a` | 変数を設定 (set-variable) | abbrev 系コマンドのプレフィックス |
| `M-g` | 行番号を指定して移動 | goto-map のプレフィックス (`M-g g` で行移動) |

undo/redo (`C-\` / `C-_`) は Emacs と割り当てが逆なので特に注意してください。
`Home`/`End`、`C-←`/`C-→` が Emacs の行頭/行末・単語移動ではない点も、
Emacs 指では特に事故りやすいところです。

キーバインドを変える
--------------------

GUI の設定ダイアログにキーバインドの編集機能はありません (一覧表示のみです)。
変更するには [Lisp で拡張する](lisp-extensions.md) の要領で `~/.xyzzy` に
`define-key` を書いてください。設定ファイルの構成全体については
[設定](configuration.md) を参照してください。
