設定
====

xyzzy の「設定」は独立した3つの場所に分かれて保存されます。**GUI で変えられる
ものと、手で書くものは別です。** どれも `-config` (環境変数 `XYZZYCONFIGPATH`)
で選んだ1つの設定ディレクトリの下に置かれます (既定は
`$XYZZY/usr/`ユーザー名`/wxp/`)。詳細は [コマンドラインオプション](command-line.md)
を参照してください。

| 何を変えるか | どこで変えるか | 保存先 | 手で編集できるか |
|---|---|---|---|
| フォント・配色・ウィンドウ位置・ファイラの列幅など | メニューの「表示」や「ツール」にある各設定ダイアログ | `xyzzy.ini` (INI 形式、`-ini` で名前変更可) | できるが、通常は GUI 経由 |
| その他の共通設定・モードごとのローカル設定 | メニューの「ツール」→「共通設定」「ローカル設定」 | `.xyzzy.history` (Lisp データ、自動生成) | 非推奨 (ダイアログを開いて上書きされる) |
| キーバインド・独自コマンドなど、GUI に無い変更 | 無し (手で編集する以外の方法が無い) | `~/.xyzzy` (無ければ `~/_xyzzy`)、Lisp コード | 前提。xyzzy 自身は書き換えない |

読み込まれる順番
----------------

起動時は次の順に読み込まれます。

  1. `~/.xyzzy` (`-q` / `-no-init-file` でスキップ可能)
  2. `.xyzzy.history` (共通設定/ローカル設定ダイアログが自動で書いた分)

`~/.xyzzy` を自分で編集していても、その後に `.xyzzy.history` が同じ変数を
上書きすることがあります。GUI の設定ダイアログで変えた項目を `~/.xyzzy` にも
同じ内容で書いていると混乱の元なので、どちらか一方に決めておくのがおすすめです。

3つが分かれている理由
----------------------

  * フォントや配色のような Win32 の描画リソースは Lisp を経由せず直接 INI
    ファイルに書かれます。GUI 側だけで完結する設定です。
  * 「共通設定」「ローカル設定」ダイアログで変えられる項目は、内部的にはただの
    Lisp 変数で、変更すると自動的に `.xyzzy.history` に書き出されます。
  * キーバインドの変更や独自のコマンド定義のように、GUI に対応する項目が無い
    ものは `~/.xyzzy` に手で書く以外に方法がありません。書き方は
    [Lisp で拡張する](lisp-extensions.md) を参照してください。

この3つの保存先が扱う項目は重ならないので、普段は意識しなくても衝突しません。
「ダイアログで変えたのに反映されない」と感じたときは、`~/.xyzzy` に同じ変数への
`setq` が残っていて起動順の後ろ (`.xyzzy.history`) を上書きしていないか、
逆に `.xyzzy.history` が古い値のまま残っていないかを疑ってください。

前回のセッションを復元する
--------------------------

**終了時に開いていたバッファとウィンドウ分割を、次の起動で復元できます。**
既定では無効なので、使うなら `~/.xyzzy` に 1 行足します。

```lisp
(setq *save-resume-info* t)
```

`M-x toggle-resume-session` でも切り替えられます (次に終了するときから効く)。

有効にすると、終了時に設定ディレクトリへ復元用のファイルが書かれ、次の起動で
読み込まれてから消えます。復元されるのは

  * 開いていたファイルのバッファ (`*scratch*` のような、ファイルを持たない
    バッファは対象外)
  * ウィンドウの分割状態と、どのウィンドウがどのバッファを出していたか
  * 各バッファのカーソル位置

です。カーソル位置は `saveplace` (`*save-place*`) でも復元されますが、そちらは
「そのファイルを次に開いたとき」で、こちらは「起動時に自動で開き直す」点が
違います。

**既定で無効にしてあるのは、起動時に前回のファイルが全部開くのを望まない人が
いるためです。** 「毎回きれいな状態で始めたい」使い方と両立しないので、
こちらから有効にはしていません。

モード行に出るもの
------------------

**モード行にはプロジェクト名と Git のブランチ名が出ます。**

```
 -- | modeline.l | xyzzy | git:topic/rich-modeline | Lisp | 12:3 45% | utf8n lf
```

左から順に、変更の有無 (`--` / `**` / `%*`)、バッファ名、プロジェクトルートの
ディレクトリ名、Git のブランチ、モード、カーソル位置と位置の割合、文字
エンコーディングと改行コードです。ファイルを持たないバッファ (`*scratch*` など)
や Git 管理外のファイルでは、出せない項目は区切りごと消えます。

`M-x toggle-rich-modeline` (`Leader t m`) で素のモード行に戻せます。並べる項目を
変えるなら `~/.xyzzy` に書きます。

```lisp
;; 位置とエンコーディングだけの短いモード行にする
(setq *modeline-segments* '(:state :buffer :branch :position))

;; 区切りを変える
(setq *modeline-separator* "  ")

;; ブランチ名の前に付ける文字列 (既定は "git:")
(setq *modeline-branch-prefix* "")

;; Git を見に行かない
(setq *modeline-git-enable* nil)
```

置ける項目は `:state` `:buffer` `:file` `:project` `:branch` `:mode`
`:major-mode` `:position` `:line-column` `:percent` `:encoding` `:ime`
`:read-only` です。文字列を混ぜるとそのまま出て、関数を混ぜるとバッファを
引数に呼ばれます (返り値の文字列がそこに入ります)。

**`~/.xyzzy` で `mode-line-format` を自分で設定している場合、このモード行は
有効になりません。** 起動時に「素の値のままかどうか」を見ているので、自分の
書式を書いている人の設定を上書きしません。

**ブランチ名は `git` を起動せず `.git/HEAD` を直接読んでいます。** サブプロセスの
起動は打鍵ごとに払える値段ではないためです。xyzzy の外でブランチを切り替えた
場合、バッファを切り替えるか 40 コマンドほど打つと追い付きます
(`*modeline-refresh-interval*`)。すぐ更新したいときは `M-x refresh-modeline`
です。リポジトリを新しく作った・消した直後は `M-x modeline-clear-cache` で
探索結果を忘れさせてください。

**色分けと右寄せはできません。** モード行は 1 色で描かれ、`%` 指定子が展開された
後の幅は Lisp 側から分からないためです。doom-modeline のような左右分割ではなく、
左から順に並べる形にしてあるのはそのためです。
