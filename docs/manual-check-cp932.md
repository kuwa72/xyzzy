実機での手作業確認 (CP932 経由の撤去)
=====================================

自動テストは Lisp から呼べる経路を見ている。ミニバッファの補完、ファイルを開く
ダイアログ、ファイラの表示、IME の再変換は目で見ないと分からないので、ここに
手順を書く。

準備
----

    C:\Users\ykuwa\Downloads\xyzzy-latest\xyzzy-amd64\xyzzy.exe

を起動する。同じ場所に修正前 (2be4424) の zip も置いてあるので、比べたければ
そちらを別のフォルダに展開する。

確認用のファイルを作る。PowerShell で:

    cd $env:USERPROFILE\Downloads
    mkdir cp932-check
    cd cp932-check
    "content" | Out-File -Encoding utf8 "日本語.txt"
    "content" | Out-File -Encoding utf8 "한국어시험.txt"
    "content" | Out-File -Encoding utf8 "简体字测试.txt"
    "content" | Out-File -Encoding utf8 "絵文字😀.txt"
    mkdir "디렉터리"
    "content" | Out-File -Encoding utf8 "디렉터리\abc.txt"

`한국어시험` と `简体字测试` は CP932 に無い文字を含む。`😀` は BMP の外。


見るもの
--------

### 1. ミニバッファの補完 (報告の「補完ができない」)

  * `C-x C-f` で `~/Downloads/cp932-check/` まで進み、`TAB` を押す。
    → 5 つの名前がそのまま出る。`?` や `??` が無い。
  * `한` まで打って `TAB`。→ `한국어시험.txt` に補完される。
  * `絵` まで打って `TAB`。→ `絵文字😀.txt` に補完される。
    以前はここで `絵文字??.txt` になっていた。
  * `디` まで打って `TAB`。→ ディレクトリ名が補完され、その下の `abc.txt` にも
    進める。

### 2. 開く (報告の「Open ができない」)

  * 上の 5 つをそれぞれ `C-x C-f` で開く。内容が `content` と読めて、
    「Invalid name」や「file not found」が出ない。
  * 開いたバッファでタイトルバーを見る。ファイル名がそのまま出て `?` にならない。
  * `C-x C-s` で保存し直せる。バックアップファイル (`~` 付き) も同じ名前で
    できる。

### 3. ファイルを開くダイアログ (報告の「ダイアログからも開けない」)

  * メニューの「ファイル」→「開く」でダイアログを出し、`cp932-check` を開く。
    → 一覧の名前が化けない。選んで開ける。

### 4. ファイラの表示

  * `M-x filer` で `cp932-check` を開く。
    → 名前の列が化けない。以前は CP932 に無い文字が `?` になっていた
    (listviewex.cc が wide → CP932 → wide の往復をしていた)。
  * ファイラから `Enter` で開ける。`c` (コピー) や `m` (移動) も名前が壊れない。

### 5. 文字として扱えること

`M-x eval-expression` で:

    (code-char 128512)          => #\😀 (char-code は 128512)
    (length "絵文字😀.txt")      => 8
    (char-code #\😀)            => 128512

バッファに `😀` を直接入力 (IME でも貼り付けでも) して、

  * カーソルが 1 回の `C-f` で越える (2 回ではない)
  * `M-x count-chars` 相当や `(point-max)` が文字数になっている
  * `C-s` で `😀` を検索して当たる

### 6. IME の再変換 (WM_IME_REQUEST)

日本語 IME を有効にして、確定済みの文字列を選択し、IME の再変換
(MS-IME なら `変換` キー、ATOK なら設定のキー) を押す。
→ 選択した文字列が候補として出る。以前は wide のバッファに CP932 の
バイトを詰めていたので、ここでゴミが出るか何も起きなかった。

### 7. 印刷のヘッダ

`M-x print-buffer` の設定で、ヘッダに `%F` (ディレクトリ付きファイル名) を
入れて `絵文字😀.txt` を印刷プレビューする。
→ ヘッダのファイル名が化けない。


### 8. ドラッグ&ドロップ (実機で見つかった不具合)

エクスプローラから `絵文字😀.txt` を xyzzy の編集窓にドロップする。
→ 開ける。以前は名前が化けて「ファイルまたはディレクトリが見つかりません」に
なっていた (WM_DROPFILES が DragQueryFileA を使っていた)。

テキストのドロップも見る。別のアプリで `a😀b` を選んで xyzzy にドロップする。
→ 3 文字として入る。

### 9. 絵文字を直接打つ (実機で見つかった不具合)

コマンド行 (`C-x C-f` や `M-x` のプロンプト) で IME や貼り付けで絵文字を
入力する。→ 落ちない。以前はプロセスごと落ちていた。

本文でも同じことをして、`C-f` 1 回で越えられること、`(point-max)` が文字数に
なっていることを見る。

### 10. 外部プロセス (make-process / xyzzyenv)

    M-x shell

を出して、絵文字やハングルを含むパスに `cd` する、あるいは

    (call-process "cmd /c echo 한국어")

を評価する。→ コマンド行が化けない。以前は xyzzyenv が GetCommandLineA で
読み直していたので '?' になっていた。

### 11. エクスプローラの「xyzzy で開く」 (xyzzycli)

`絵文字😀.txt` を右クリックして xyzzy に関連付けて開く (または
`xyzzycli.exe 絵文字😀.txt` を実行する)。→ 起動中の xyzzy でそのファイルが
開く。

**注意**: xyzzycli.exe と xyzzy.exe の間で渡す S 式のエンコーディングが
CP932 から UTF-8 に変わった。同じ zip の組で使うこと。片方だけ古いものに
差し替えると非 ASCII が化ける。


### 12. BMP 外の文字を打った後のカーソルとアンドゥ (実機で見つかった不具合)

Windows は BMP 外の文字 (絵文字など) を WM_CHAR / WM_IME_CHAR で code unit
2 個 = メッセージ 2 通に分けて渡してくる。以前はそれをそのままキューに
載せていたので self-insert-command が 2 回走り、サロゲートの片割れが
別々の文字としてバッファに入っていた。バッファの code point 数がその場で
壊れるので、次の 3 つが同時に起きる。

本文で絵文字を 1 個打って:

  * カーソルが文字の直後に来る (以前は 1 個余分に進んだ)
  * `C-f` / `C-b` 1 回で越える
  * `(point)` が文字数で数えられている
  * `C-/` (アンドゥ) で絵文字だけが消え、リドゥで戻る
    (以前はどちらもずれた)
  * `Backspace` 1 回で消える

コマンド行 (`C-x C-f` や `M-x` のプロンプト) で絵文字を打って:

  * 落ちない。空のバッファに片割れが入ると、まだ進める筈なのに chunk が
    尽きるので、以前はここでプロセスごと落ちていた。

貼り付けでも同じことを見る。`(length s)` が文字数になっていること
(以前はサロゲート 2 個で 2 と数えていた)。

### 13. C-q で BMP 外の文字を入れる

  * `C-q` を押して絵文字を貼り付ける、または IME で入れる。→ そのまま入る。
    以前は `read-char` が 16bit に切り詰めていたので 0xF600 (メタ機能キー)
    が本文に入った。
  * `C-q u 1F600 RET` → 😀 が入る。以前は `unicode-char` がサロゲート
    2 要素の文字列を返していたので、文字を期待している側と食い違っていた。

### 14. サブプロセスの多バイト文字 (実機で見つかった不具合)

    M-x shell

`*eshell*` の既定は pwsh / powershell。日本語を含む出力 (`ls`,
`Get-ChildItem`, `echo 日本語`) が化けないこと。

`*default-process-encoding*` を sjis から UTF-8 に変えた。Windows 10 1809
以降は make-process が ConPTY 経由になり、conhost が子プロセスの出力を
コンソールコードページから UTF-8 に変換して pty に流す (入力も UTF-8 と
して解釈される)。子が cmd.exe でも pwsh でも変わらない。ここが sjis の
ままだと多バイト文字が全部化ける。

ConPTY が使えない環境 (1809 未満) では生パイプになり、子が CP932 で
出力する。その場合は

    (setq *default-process-encoding* *encoding-sjis*)

で戻せる。


それでも直っていない既知の点
----------------------------

  * 正規表現の文字クラス (`[...]`) は BMP 内だけを表にしているので、BMP 外の
    文字を範囲に入れた指定は効かない。リテラルとしての検索は効く。
  * 書庫 (lha/zip 等) の中のファイル名は DLL が ANSI 専用なので CP932 のまま。
  * ホスト名は ASCII でなければならない (punycode の変換は入れていない)。
  * サロゲートの片割れを Lisp から明示的に挿入 (`(insert (code-char #xD83D))`)
    すると、バッファの code point 数と chunk の数え方が食い違う。通常の
    編集・入力経路では起きない。踏んでも落ちないようにはしたが
    (`forward_char` が末尾で clamp する)、位置の計算はずれる。
  * キーシーケンスの表示 (`C-x C-f` のエコー) は 16bit のままなので、
    BMP 外の文字を含むキー列の表示は崩れる。入力そのものには影響しない。
  * ターミナル (ConPTY) の画面モデル (`TermCell::ch`) は 16bit なので、
    子プロセスが BMP 外の文字を出しても画面には出ない。打ち込む側
    (xyzzy → pty) は 4 バイトの UTF-8 で送るようにした。
