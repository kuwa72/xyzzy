変更
----

  * `lisp/foreign.l` の `size_t`/`time_t`/`ptrdiff_t`/`void*` のポインタ幅
    判定を、コンパイルした exe 自身の `*features*` を読み取り時に見る
    `#+:64bit`/`#-:64bit` から、ロードした側の `*features*` を見る実行時
    分岐に変えた。これにより byte compile 済みの `.lc` は i686/x86_64 間
    で真にポータブルになり、`tools/bytecompile.sh`/`tools/run-tests.sh` が
    アーキごとに `.lc` を全消し再コンパイルしていたスタンプ機構
    (`lisp/.bytecompile-arch`) が不要になったため削除した。
  * `tools/bytecompile.sh` が `lisp/*.l` を編集しても `--force` を付け
    忘れると `.lc` を再コンパイルしない (アーキスタンプが一致していると
    ファイルの鮮度を見ずに即終了していた) 問題を修正した。
    `misc/bytecompile-batch.l` が `force-recompile` を常に `t` で呼んで
    いたため、`misc/makelc.l` にすでにあった `.l`/`.lc` の mtime 比較が
    死んでいたのが原因。新しく `tools/lc-stale.sh` に切り出した鮮度判定
    を `tools/bytecompile.sh` の事前チェックとして使い、変更の無い
    ファイルは再コンパイルせず、変更したものだけ拾うようにした。
    `tools/run-tests.sh` も同じ鮮度判定で `.lc` が古いままテストを走らせ
    ないようにガードし、宣言だけで未実装だった `--bytecompile` オプション
    を実際に配線した。
  * `tools/x` の Docker 開発環境に `ccache` を導入し、`configure` に
    `CMAKE_C_COMPILER_LAUNCHER`/`CMAKE_CXX_COMPILER_LAUNCHER` を渡す
    ようにした。`_build/$ARCH` はチェックアウトごとの生成物で
    `git worktree` の兄弟間で共有できないため、比較用に別コミットを
    並行ビルドしようとすると毎回フルビルドになり2分以上かかっていた。
    ccache はソースの内容とコンパイラフラグでキャッシュキーを決めるので
    worktree の場所やコミットに関係なく再利用でき、実測でも2回目の
    ビルドが2分26秒から13秒に短縮された。合わせて `tools/x` が
    `git worktree add` した兄弟チェックアウトを個別に
    `/siblings/<ディレクトリ名>` としてコンテナ内にマウントするように
    した (単一チェックアウトのみの場合は何も変わらない)。
  * ncurses フロントエンドで、ターミナルバッファ (`*Shell*` など) 内の
    矢印キー・Home/End・PageUp/Down 等が pty へ正しく届いていなかった
    のを直した。`map_ncurses_key` が旧 Char encoding の `CCF_LEFT`
    (0xff04) 等を素の値のまま返しており、`terminal_key_to_bytes` 側は
    新 lChar encoding (kind タグ付き) を前提にしていたため、kind タグの
    無いその値が「コードポイント 0xff04 の文字」と誤認識され、本来送る
    べき `ESC[D` の代わりに全角パーセント風の文字の UTF-8 バイト列が pty
    に送られていた。bash の readline や `less`/`vim`、対話 CLI (Claude
    Code 等) がカーソルキーで行編集や画面操作をしようとしても何も
    反映されなかったのがこれ。`lc_from_ccf` を通して kind=FNKEY 付きの
    正規の lChar に変換するようにした。
  * Win32 (ConPTY) のターミナルバッファで、マウス報告を有効にしている
    アプリ (`claude` 等) が動いている別ウィンドウをクリックしても選択
    ウィンドウが切り替わらなかったのを直した。マウス報告が有効な間は
    クリックが `send_mouse_to_terminal` で直接 pty へ流れ、通常
    `#\LBtnDown` → `mouse-left-press` が呼ぶ `set-window` を一切経由
    しなかったのが原因。選択が移らないので、そのウィンドウでは
    `selected_window()` を見ているターミナルのカーソル描画も効かず
    (キー入力自体は飛んでいて内部の位置は動くのに、画面上のカーソルだけ
    動かないように見えた)、キー入力もそのウィンドウには届かなかった。
    DOWN クリックのときだけ pty へ送る前にウィンドウを選択するようにした。
  * 最近のターミナル実装 (kitty / WezTerm / iTerm2 等) を参考にターミナル
    エミュレータ (`src/core/term.cc`) を見直し、次を直した/足した。
    - ncurses フロントエンドで、`Terminal::feed` が積んだ DSR / DA の
      応答 (カーソル位置・端末種別への問い合わせへの返事) を pty へ
      書き戻す処理がそもそも無かった。win32 側 (ConPTY) には元からあった
      のに ncurses 側だけ抜けていた。位置を問い合わせてから描画する
      TUI ほど影響が大きく、起動時に応答待ちで止まる/既定値で誤った
      レイアウトを組む原因になっていた。
    - REP (`CSI Pn b`、直前の文字を Pn 回繰り返す) が未実装で、これを
      使う出力 (罫線・進捗バー等の帯域節約) を送られると繰り返される
      はずの文字がそのまま欠落していた。対応した。
    - フォーカス報告 (DECSET 1004) はモードの状態こそ持っていたが、
      実際に `ESC[I` / `ESC[O` を送る処理が無く要求しても何も届かない
      死んだ機能だった。tmux 等のマルチプレクサがペイン切り替えで
      やるのと同じように、選択ウィンドウが切り替わったとき
      (`Window::set_window`) に外れる側/入る側のターミナルへ送るように
      した。
    どちらも ncurses 実機で `cat -A` を使い、応答/繰り返し/フォーカス
    バイトが実際に pty へ届くことを確認した。
    - Synchronized output (`CSI ?2026h/l`。kitty が広めた、フレーム単位
      の再描画を一括で見せてちらつきを防ぐモード) を実装した。区間中は
      画面の更新を溜めておき、閉じた時点でまとめて反映する。アプリが
      `l` を送らずに固まった場合の保険として、2 秒経っても閉じなければ
      次の出力が来た時点で強制的に区間を終わらせる (仕様が推奨する安全
      策で、無いと再描画が永久に止まって見える)。ncurses 実機で、区間
      中は新しい出力が一切画面に出ず、閉じた瞬間にまとめて出ることを
      確認した。
    - OSC 52 (クリップボード書き込み) に対応した。読み出し (`Pd == "?"`)
      は実装していない — リモートのアプリに他アプリがコピーした内容を
      覗き見させる経路になるため、kitty/WezTerm/foot など最近の端末の
      多くも既定は書き込みのみにしている。win32 (ConPTY) は
      `OpenClipboard`/`SetClipboardData` で直接書き込む。ncurses は
      自前のクリップボード API を持たないので、OSC をそのまま自分を
      包んでいる本物の端末へ中継する (tmux の allow-passthrough と同じ
      発想)。ncurses 実機で、tmux の `set-clipboard on` を使って中継先
      まで正しい内容が届くことを確認した。
