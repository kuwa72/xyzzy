xyzzy リリースノート
====================

  * バージョン: 0.2.6.8
  * リリース日: 2026-08-21
  * ホームページ: <https://github.com/kuwa72/xyzzy>


このリリースについて
--------------------

kuwa72/xyzzy の正式版である。[snmsts/xyzzy](https://github.com/snmsts/xyzzy)
の `modern` を土台に、こちらで見つけたバグ修正と、ターミナル・文字周りの
作り直しを載せてある。

土台の側 (ARM64/x86-64 対応、Win32 API の Unicode 化、CMake 化、tree-sitter、
ncurses フロントエンドなど) は 0.2.6.3 のリリースノートを参照。ここには
0.2.6.3 以降にこの木で入れた分を書く。0.2.6.8-preview / -preview2 / -pr3 で
出していた分もまとめてある。

このリリースから `main` が開発の本流になる。


ターミナル
----------

ConPTY を使ったターミナルバッファを実用に耐えるところまで直した。

  * 色。24bit 色、256 色パレット、OSC に対応した。地色が黒固定だったのも
    直してある。
  * 桁ずれ。Ambiguous 幅の文字をターミナルでは 1 桁で数えるようにした。
    向こう側で動くアプリ (wcwidth や string-width を使う TUI) が 1 桁で
    数えるので、こちらが 2 桁で数えると罫線を使った表やサイドバーが
    1 文字ごとに崩れていた。マウス報告と DSR/DA の応答も直した。
  * 特殊記号が豆腐になるのを直した。ターミナルの描画がその code point の
    glyph を持つフォントを `GetGlyphIndicesW` で選び、結果を覚えるように
    なっている。
  * Unicode。ターミナルが受け取った文字を旧 internal encoding に変換して
    いたのをやめた。
  * 矢印キー、IME の変換ウィンドウの位置、貼り付け (bracketed paste)。
  * ホイールを pty へ流すようにした。
  * 描画をまとめ、変わった行だけ描くようにした。80x50 の再描画で GDI 呼び出し
    4000 組を出していたのを、同じ属性が続くセルを 1 回の `ExtTextOutW` に
    まとめる形にしてある。ホイールやドラッグの重さが取れた。
  * 窓をリサイズしてもターミナルが追従しないのを直した。桁数・行数を窓に
    合わせて ConPTY に伝える処理が再描画の一方の経路にしか無く、リサイズ後に
    何か打つまで子プロセスが古い大きさのままだった。


フォント
--------

  * Nerd Font のアイコン用にフォント枠を足した (`:symbol`)。Private Use Area
    (U+E000-U+F8FF と U+F0000 以降) をこの枠に振る。既定は
    `Symbols Nerd Font Mono` で、入っていなければ本文と同じ face に落ちるので、
    パッチ済みの Nerd Font を本文に使っているならそのまま出る。設定画面で
    この枠を選ぶと、見本欄が Nerd Font の代表 7 字に変わり、`GetGlyphIndicesW`
    で数えたグリフの数を出す。
  * フォント設定に絞り込み入力欄を足した。打った文字を含む face だけが一覧に
    残る。等幅フォントを何十個も並べて探す必要が無くなる。


文字とファイル
--------------

  * 文字を 1 個 princ すると 0xFF を超える部分が落ちるのを直した。
    `(princ "平成")` は正しいのに `(princ (char "平成" 0))` が `"s"` になる、
    という壊れ方をしていた。
  * 絵文字を打つと落ちる、ドロップしたファイル名が化ける、のを直した。
  * BMP 外の文字を 1 打鍵 1 文字として入力できるようにした。
  * `code-char` が `char-code-limit` 未満のすべてに文字を返すようにした。
  * ファイル入出力の外から CP932 経由をなくした。
  * ANSI の Win32 API をやめた (コマンド行、起動ヘルパ、クラッシュログ)。
  * 32bit の DLL 呼び出しが自分のフレームを踏み潰すのを直した。呼ばれた側の
    フレームが呼び出しヘルパの戻り番地の上に乗り、`ret` がどこでもない番地へ
    飛んでいた。FFI がまともに使えるようになる。
  * `%#g` の書式、`ash` の幅を超える右シフト、`last` のドットリスト、
    `code-char`、ファイラのジャンクション削除、令和と 2016 年以降の祝日法改正。


ビルドと配布
------------

  * Windows 版のツールチェインを 2 つに絞った。ふだんの開発は llvm-mingw
    (Clang/LLD + UCRT) で、x86 / x86-64 / ARM64 を Linux や macOS から
    クロスビルドできる。`tools/x` 一式で docker だけあれば建てられ、Wine で
    テストスイートまで回る。MSVC は上流互換とリリース物のために残す。
    MSYS2 / Cygwin は対応しない。
  * ARM64 も llvm-mingw で建てるようにした。コードジェネレータはターゲット
    向けにビルドされて x86 の Wine では動かせないので、`tools/x arm-prep` が
    x86_64 側で先に `src/core/gen/` を作る。
  * バイトコンパイルが `startup.l` の途中で止まり、81 ファイルが取り残されて
    いたのを直した。配布物の `.lc` が揃う。
  * tree-sitter の文法をパッケージに入れるようにした。
  * パッケージに `.lc` のアーキ印を同梱するようにした。32bit と 64bit で
    `.lc` は互換ではないので、取り違えたまま起動して FFI が妙な値を返す、
    という壊れ方を防ぐ。


既知の問題
----------

  * 32bit の llvm-mingw ビルドでは、FFI の呼び出しでハードウェア例外が起きた
    とき Lisp のコンディションにならずプロセスが落ちる。LLVM が 32bit x86 の
    SEH を扱えないためで、MSVC ビルドには影響しない。テストは該当 3 件を
    除外してある。
  * ARM64 のバイナリを実際に動かす確認は MSVC のジョブ (windows-11-arm) だけで
    行っている。x86 の Wine では ARM64 の実行ファイルを起動できない。
