xyzzy リリースノート
====================

  * バージョン: 0.5.0
  * リリース日: 2026-08-26
  * ホームページ: <https://github.com/kuwa72/xyzzy>


このリリースについて
--------------------

**ターミナルバッファを実際に使えるようにしたリリースである。** 0.4.0 で
`M-x shell` のターミナルは入ったが、WSL の中で Claude Code のような TUI を
動かして日常的に触ってみると、土台に穴が空いていることが次々に分かった。
カーソルが動かない、スクロールバックが遡れない、マウスで選択できない、
PowerShell の BackSpace が 1 語消す。0.5.0 はこれを一通り塞いだものである。

**後半の 4 つは全部同じ根っこだった。** ターミナルバッファは buffer 本文を
持たず `TermCell` の格子を直接描いている。だから Buffer を経由する機能 —
ホイール (`mouse-wheel-handler` が point を動かす)、スクロールバー
(`count_lines()` を数える)、マウス選択 (`mouse-left-press` が point を
動かす) — は、エラーも出さず黙って何もしない。それぞれ端末側の状態を
見るように書き直した。

合わせて、最近のターミナル実装 (kitty / WezTerm / iTerm2) を参考に
エミュレータ本体を一通り見直し、synchronized output と OSC 52 を実装し、
REP・フォーカス報告・ncurses 側の DSR/DA 応答の抜けを埋めた。


ターミナルのカーソルとキー入力
------------------------------

  * ターミナルバッファで、カーソルが動いただけでは画面のカーソルが動か
    なかったのを直した (Win32 / ncurses 両方)。`*Shell*` で bash や
    PowerShell の行編集をカーソルキーでしても、Claude Code のような TUI が
    入力欄のカーソルを動かしても、画面上のカーソルは前の位置に取り残され、
    何か文字を打って初めて正しい位置に飛ぶ、という状態だった。

    再描画は `Terminal::dirty()` で判定しているが、`t_dirty` を立てていた
    のはセルの中身を書き換える場所だけで、CUP / CUF / CUB / CR のように
    カーソルだけを動かすシーケンスでは立てていなかった。描画側はカーソルを
    セルの反転で重ねている = カーソル位置も画面の一部なので、中身が同じでも
    描き直しが必要になる。個々のシーケンスに `t_dirty = 1` を撒くと必ず
    取りこぼすので、`feed()` の前後でカーソル位置と表示状態を比べて判定
    するようにした (同じ `feed()` の中で動いて戻った場合は見た目が変わら
    ないので、正しく「変化なし」になる)。ncurses 実機で、修正前は 3 回
    左キーを押しても端末のカーソルが動かず、修正後は 3 桁戻ることを
    tmux の `cursor_x` で確認した。
  * ncurses フロントエンドで、ターミナルバッファ (`*Shell*` など) 内の
    矢印キー・Home/End・PageUp/Down 等が pty へ正しく届いていなかった
    のを直した。`map_ncurses_key` が旧 Char encoding の `CCF_LEFT`
    (0xff04) 等を素の値のまま返しており、`terminal_key_to_bytes` 側は
    新 lChar encoding (kind タグ付き) を前提にしていたため、kind タグの
    無いその値が「コードポイント 0xff04 の文字」と誤認識され、本来送る
    べき `ESC[D` の代わりに全角パーセント風の文字の UTF-8 バイト列が pty
    に送られていた。bash の readline や `less`/`vim`、対話 CLI (Claude
    Code 等) がカーソルキーで行編集や画面操作をしようとしても何も
    反映されなかったのがこれ。`lc_from_ccf` を通して kind=FNKEY 付きの
    正規の lChar に変換するようにした。
  * Win32 のターミナルバッファで、BackSpace が PowerShell では「カーソル
    前の 1 語を消す」動きになっていたのを直した。実端末 (xterm / Windows
    Terminal / kitty …) が BackSpace キーに割り当てているのは DEL (0x7f)
    で、0x08 の方は Ctrl+BackSpace である。PSReadLine はそれに従って 0x08
    を `BackwardDeleteWord` に割り当てているのに、こちらは 0x08 を送って
    いた (bash は 0x08 と 0x7f の両方を `backward-delete-char` にして
    いるので出なかった)。実際に `powershell.exe` へ両方のバイトを送り、
    0x7f が 1 文字・0x08 が 1 語消すことを確かめた上で DEL に変えた。
    Win32 では BackSpace と Ctrl+H の区別が付かない (VK_BACK は WM_CHAR
    0x08 になり Ctrl+H と同じ値) ので、エディタ本体が両者を同じ `#\C-h`
    として扱っているのと同じくここでも区別しない。ncurses 側は ncurses が
    区別してくれるので元から DEL を送っていた。
  * ターミナルバッファで、アプリが DECTCEM (`CSI ?25l`) でカーソルを消して
    いる間もブロックカーソルを描き続けていたのを直した。TUI は自前の
    カーソルを反転セルで描くために実カーソルを消すので、両方出ると二重に
    見えていた。合わせて Win32 側で、スクロールバックを遡っている間に
    カーソルが「その表示行にあるかのように」描かれていたのも直した
    (表示は offset ぶん下へずれるので、カーソルも同じだけずらし、画面外に
    出たら描かない。ncurses 側は元から遡り中は隠していた)。


ターミナルのマウスとスクロールバック
------------------------------------

いずれも Win32 版の話である。ncurses 版ではスクロールバックの表示も選択も
外側の本物の端末 (Windows Terminal や tmux) の仕事になる。

  * マウスによるテキスト選択ができるようにした。ターミナルバッファは
    buffer 本文を持たない (表示は `TermCell` を直接描いている) ので、
    `mouse-left-press` が動かすのは常に空の buffer の point であり、
    ドラッグしても何も掴めなかった。格子の座標で範囲を持ち、描画時に
    反転して見せ、ボタンを離した時点でクリップボードへ入れる (PuTTY や
    xterm と同じ copy-on-select)。貼り付けは既存の `#\C-v`
    (`terminal-paste`) がそのまま使える。アプリがマウス報告を要求して
    いる間 (claude code 等) はドラッグはアプリのものだが、Shift を押して
    いる間だけはこちらが取る — 実端末がみなそうしているのと同じ逃げ道で
    ある。選択は格子の座標なので、出力が来た時とスクロールバックを動かし
    た時は指す文字が変わってしまうため解除する。
  * マウスホイールがスクロールバックを遡れなかったのを直した。アプリが
    マウス報告を要求していない間、ホイールは Lisp の
    `mouse-wheel-handler` へ渡っていたが、あちらが動かすのは buffer の
    point で、ターミナルの表示は `TermCell` を直接描いていて buffer 本文を
    見ていない。つまり回しても何も起きなかった。ターミナルバッファでは
    端末自身のスクロールバック (`S-PageUp` と同じもの) を動かすようにした。
    マウス報告が有効な間は従来どおりホイールを pty へ流す (アプリ側が
    スクロールを解釈する)。
  * スクロールバックが溜まっていても縦スクロールバーが動かなかったのを
    直した。`update_vscroll_bar` は行数を `Buffer::count_lines()` から
    取るが、ターミナルバッファは buffer 本文を持たないので常に 0 行、
    つまり「1 ページに収まっている」扱いになっていた。ターミナルバッファ
    では行数・位置を端末のスクロールバック (`scrollback_count` /
    `scrollback_offset`) から取るようにした。バーの操作 (つまみのドラッグ、
    矢印、余白クリック) も同じ理由で `scroll_window` = buffer の point を
    動かしても効かないので、ホイールと同じくスクロールバックに向けた。
  * マウス報告を有効にしているアプリ (`claude` 等) が動いている別ウィンドウ
    をクリックしても選択ウィンドウが切り替わらなかったのを直した。マウス
    報告が有効な間はクリックが `send_mouse_to_terminal` で直接 pty へ流れ、
    通常 `#\LBtnDown` → `mouse-left-press` が呼ぶ `set-window` を一切経由
    しなかったのが原因。選択が移らないので、そのウィンドウでは
    `selected_window()` を見ているターミナルのカーソルが描かれず、キー入力
    もそのウィンドウには届かなかった。DOWN クリックのときだけ pty へ送る
    前にウィンドウを選択するようにした。


ターミナルエミュレータの見直し
------------------------------

最近のターミナル実装 (kitty / WezTerm / iTerm2 等) を参考に
`src/core/term.cc` を一通り見直し、次を直した/足した。

  * Synchronized output (`CSI ?2026h/l`。kitty が広めた、フレーム単位の
    再描画を一括で見せてちらつきを防ぐモード) を実装した。区間中は画面の
    更新を溜めておき、閉じた時点でまとめて反映する。アプリが `l` を送らず
    に固まった場合の保険として、2 秒経っても閉じなければ次の出力が来た
    時点で強制的に区間を終わらせる (仕様が推奨する安全策で、無いと再描画
    が永久に止まって見える)。ncurses 実機で、区間中は新しい出力が一切
    画面に出ず、閉じた瞬間にまとめて出ることを確認した。
  * OSC 52 (クリップボード書き込み) に対応した。読み出し (`Pd == "?"`)
    は実装していない — リモートのアプリに他アプリがコピーした内容を
    覗き見させる経路になるため、kitty/WezTerm/foot など最近の端末の
    多くも既定は書き込みのみにしている。win32 (ConPTY) は
    `OpenClipboard`/`SetClipboardData` で直接書き込む。ncurses は
    自前のクリップボード API を持たないので、OSC をそのまま自分を
    包んでいる本物の端末へ中継する (tmux の allow-passthrough と同じ
    発想)。ncurses 実機で、tmux の `set-clipboard on` を使って中継先
    まで正しい内容が届くことを確認した。
  * ncurses フロントエンドで、`Terminal::feed` が積んだ DSR / DA の
    応答 (カーソル位置・端末種別への問い合わせへの返事) を pty へ
    書き戻す処理がそもそも無かった。win32 側 (ConPTY) には元からあった
    のに ncurses 側だけ抜けていた。位置を問い合わせてから描画する
    TUI ほど影響が大きく、起動時に応答待ちで止まる/既定値で誤った
    レイアウトを組む原因になっていた。
  * REP (`CSI Pn b`、直前の文字を Pn 回繰り返す) が未実装で、これを
    使う出力 (罫線・進捗バー等の帯域節約) を送られると繰り返される
    はずの文字がそのまま欠落していた。対応した。
  * フォーカス報告 (DECSET 1004) はモードの状態こそ持っていたが、
    実際に `ESC[I` / `ESC[O` を送る処理が無く要求しても何も届かない
    死んだ機能だった。tmux 等のマルチプレクサがペイン切り替えで
    やるのと同じように、選択ウィンドウが切り替わったとき
    (`Window::set_window`) に外れる側/入る側のターミナルへ送るように
    した。

DSR/DA・REP・フォーカス報告は ncurses 実機で `cat -A` を使い、
応答・繰り返し・フォーカスのバイトが実際に pty へ届くことを確認した。


ビルドと配布
------------

  * `lisp/foreign.l` の `size_t`/`time_t`/`ptrdiff_t`/`void*` のポインタ幅
    判定を、コンパイルした exe 自身の `*features*` を読み取り時に見る
    `#+:64bit`/`#-:64bit` から、ロードした側の `*features*` を見る実行時
    分岐に変えた。これにより byte compile 済みの `.lc` は i686/x86_64 間
    で真にポータブルになり、`tools/bytecompile.sh`/`tools/run-tests.sh` が
    アーキごとに `.lc` を全消し再コンパイルしていたスタンプ機構
    (`lisp/.bytecompile-arch`) が不要になったため削除した。
  * `tools/bytecompile.sh` が `lisp/*.l` を編集しても `--force` を付け
    忘れると `.lc` を再コンパイルしない (アーキスタンプが一致していると
    ファイルの鮮度を見ずに即終了していた) 問題を修正した。
    `misc/bytecompile-batch.l` が `force-recompile` を常に `t` で呼んで
    いたため、`misc/makelc.l` にすでにあった `.l`/`.lc` の mtime 比較が
    死んでいたのが原因。新しく `tools/lc-stale.sh` に切り出した鮮度判定
    を `tools/bytecompile.sh` の事前チェックとして使い、変更の無い
    ファイルは再コンパイルせず、変更したものだけ拾うようにした。
    `tools/run-tests.sh` も同じ鮮度判定で `.lc` が古いままテストを走らせ
    ないようにガードし、宣言だけで未実装だった `--bytecompile` オプション
    を実際に配線した。
  * `.github/workflows/mingw.yml` で、`.lc` のキャッシュが当たると必ず
    テストが `run "tools/x bytecompile" first` で落ちるようになっていたのを
    直した。`tools/run-tests.sh` の鮮度判定 (`tools/lc-stale.sh`) は `.l` と
    `.lc` の mtime を比べるが、`actions/checkout` は全ての `.l` にチェック
    アウト時刻を打つ一方、復元された `.lc` は保存時の mtime を保つので、
    `.l` の方が必ず新しくなる。キャッシュキーは `lisp/**/*.l` の内容ハッシュ
    なので、当たったこと自体が mtime より強い保証 (ソースはその `.lc` を
    作ったときとバイト単位で同一) になる。復元後に `touch` してそれを
    表明するようにした。これが無いと lisp/ を触らない PR でも毎回ライブラリ
    全体を再コンパイルすることになり、キャッシュの意味が無くなる。
  * `tools/x` の Docker 開発環境に `ccache` を導入し、`configure` に
    `CMAKE_C_COMPILER_LAUNCHER`/`CMAKE_CXX_COMPILER_LAUNCHER` を渡す
    ようにした。`_build/$ARCH` はチェックアウトごとの生成物で
    `git worktree` の兄弟間で共有できないため、比較用に別コミットを
    並行ビルドしようとすると毎回フルビルドになり2分以上かかっていた。
    ccache はソースの内容とコンパイラフラグでキャッシュキーを決めるので
    worktree の場所やコミットに関係なく再利用でき、実測でも2回目の
    ビルドが2分26秒から13秒に短縮された。合わせて `tools/x` が
    `git worktree add` した兄弟チェックアウトを個別に
    `/siblings/<ディレクトリ名>` としてコンテナ内にマウントするように
    した (単一チェックアウトのみの場合は何も変わらない)。


ドキュメント
------------

  * `docs/user/keybindings.md` のターミナル節にマウス操作を書き足し、
    `docs/user/features.md` のターミナルエミュレータの説明を実態に合わせた。
