xyzzy リリースノート
====================

  * バージョン: 0.3.1
  * リリース日: 2026-08-22
  * ホームページ: <https://github.com/kuwa72/xyzzy>


このリリースについて
--------------------

**エディタの動作は 0.3.0 と変わらない。** 中身は開発とリリースの仕組みの整備だけ
である。使うだけなら 0.3.0 のままでよい。

なぜそれで版を切るのかというと、リリース経路そのものを作り直したので、一度通して
おきたかったからである。0.3.1-rc1 はそのための版である。


テストを結果で止めるようにした
------------------------------

テストは MSVC・llvm-mingw のどちらでも `continue-on-error` で走っていて、赤くても
マージもリリースもできた。しかも実際にどの構成でも 8〜10 件が恒常的に落ちていたので、
本物の regression が来ても既存の失敗と見分けが付かない状態だった。

既知の失敗を名前で `misc/known-failures/` に書き出し、**それ以外**で止めるように
した。リストに載っているテストが通るようになった場合も止める。掃除されないリストは
すぐ意味を失うためである。

  * MSVC x86 は 8 件、x64 と ARM64 は 10 件、mingw は両アーキとも 10 件。どれも
    実測と一致している
  * 落ちたテスト名はログではなくテストフレームワークの内部から取る。mingw x86_64 は
    「10 件失敗」と言いながら `...Failed` を 9 行しか出さないことがあり、ログは
    一覧として信用できない。名前の無かったその 1 件は `hmac-sha2-test-case-3` で、
    gate を入れた最初の実行が名指しして判明した


リリースの検証
--------------

タグを打てばリリースは出るが、その中身が正しいかを誰も見ていなかった。以下を
検証するようにした。いずれもビルドの前に 10 秒で終わる。

  * タグの数値部と `CMakeLists.txt` の `project(xyzzy VERSION ...)` の一致。
    ZIP の名前は CMake 由来、インストーラのバージョンはタグ由来なので、食い違うと
    1 つのリリースに別々の版番号が並び、しかもバイナリ自身は 3 つ目の答えを返す
  * リリースノートの存在。以前は無いと本文に "No release notes found" と書いて
    公開に成功していた
  * タグが `main` 上にあること
  * 成果物が 3 アーキ分そろっていること

あわせて、接尾辞付きのタグ (`-rc1`、`-preview`) を prerelease として公開するように
した。従来は正式リリース扱いで出ていた。成果物には `SHA256SUMS` を同梱する。


手順と、手順を守らせる仕組み
----------------------------

`RELEASING.md` に手順を書き、`tools/release-prep.sh` が版上げとノートの用意を
まとめてやるようにした。リリースノートは `docs/release-note-next.md` に書き足して
いき、リリース時に改名する。ノートを必須にした分、まとめて書く負担が集中しないように
するためである。

文書は読まれなければ効かないので、機械で判定できるものは git hook に降ろした
(`.githooks/`)。`main` への直接 push、`CMakeLists.txt` と食い違うタグ、ノートの無い
タグ、再ビルドされた tree-sitter DLL の混入を、手元で止める。

その他、依存 action の更新を dependabot に見せ、toolchain の腐りを見つけるために
mingw を毎晩・MSVC を毎週動かすようにした。
