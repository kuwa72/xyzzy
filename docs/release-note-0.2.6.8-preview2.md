xyzzy リリースノート
====================

  * バージョン: 0.2.6.8-preview2
  * リリース日: 2026-08-20
  * ホームページ: <https://github.com/kuwa72/xyzzy>


このリリースについて
--------------------

0.2.6.8-preview に続くプレビュー版である。

**このリリースのバイナリの動作は preview と変わらない。** 配布している exe は
MSVC でビルドしており、preview からの差分はビルド基盤と検証環境に入っている。
MSVC が読むソースの変更は、リソーススクリプトのパス区切りを `\` から `/` に
した分と、`ShObjIdl.h` を実際のファイル名 `shobjidl.h` に合わせた分だけで、
どちらも Windows 上では以前と同じものになる。

入れ替えを急ぐ理由は無い。preview で構わない。


ビルドと検証環境
----------------

Windows マシンが無くても Windows 版をビルドして動かせるようにした。llvm-mingw
(Clang/LLD) でクロスビルドし、Wine で走らせる。docker だけあればよい。

```bash
tools/x image                # コンテナイメージを作る (初回のみ)
tools/x build     x86_64     # i686 / aarch64 も指定できる
tools/x bytecompile x86_64
tools/x test      x86_64     # テストスイートを Wine で流す
```

  * **ARM64 もクロスビルドの対象になった。** 塞いでいたのはコードジェネレータ
    である。`gen-src1` / `gen-src2` はターゲット向けにビルドされてビルド中に
    実行されるが、x86 の Wine では ARM64 の PE を起動できない。出力はアーキ
    テクチャによらず同じ内容で、置き場所もソースツリーの中なので、走らせられる
    ビルドが先に書けばよい。`tools/x arm-prep` がそれをする。ARM64 のバイナリ
    を実際に走らせるのは、これまでどおり MSVC の windows-11-arm ジョブである。

  * CI (`mingw` ワークフロー) が i686 / x86_64 / aarch64 の 3 アーキで回る。
    リリース用のバイナリは従来どおり MSVC の `build` ワークフローが作る。

  * クロスビルドのツールチェインを mingw-w64 GCC から llvm-mingw に寄せた。
    1 つで i686 / x86_64 / aarch64 を賄えること、この木がすでに Clang 前提に
    なっていること、GCC の `aarch64-w64-mingw32` は SEH と C++ 例外が未実装で
    この木では使えないことが理由である。


バグ修正
--------

  * 32bit の Clang ビルドで、DLL を呼ぶと呼び出し元のフレームを踏み潰していた
    のを直した。

    **MSVC でビルドした配布バイナリには影響しない。** クロスビルド (llvm-mingw
    i686) だけの不具合である。

    `funcall_dll` は引数を積んだ領域を ESP に入れて DLL を呼ぶ。ESP が指す先は
    呼ばれた関数のスタックの上端なので、そこから下へフレームが伸びる。MSVC 版は
    この asm が `funcall_dll` の中にあり、その時点の ESP がすでにフレームの
    最下部なので下に生きているものが無い。Clang 版は `__try` を使うために別の
    関数に切り出してあり、そこから呼び出し元の領域を渡していたので、呼ばれた側
    のフレームが切り出した関数自身の戻り番地を上書きしていた。最後の `ret` は
    DLL の置き土産へ飛び、飛び先は渡した引数によって変わる。引数を自分の
    フレームの最下部に取り直すようにした。

  * 呼び出し規約の指定を `LISP_CALL` に集約した。Lisp 関数の ABI は自分同士で
    揃っていればよく、MSVC x86 は `/Gz` で、Clang は注釈しないことで揃う。

  * tree-sitter が同梱する ICU のヘッダを GCC でも見つけられるようにした。

  * CMake 3.30 より古い CMake でも configure できるようにした (`CMP0169`)。


テスト
------

Wine 上でテストスイートが最後まで走るようになった。これまでは意図的に例外を
投げるテストでプロセスが落ち、そこから先が測れていなかった。

| 構成 | 結果 |
|---|---|
| llvm-mingw x86_64 (Wine) | 568 tests: 557 passed, 11 failed (skipped 8) |
| llvm-mingw i686 (Wine) | 565 tests: 554 passed, 11 failed (skipped 11) |
| MSVC x86 (Windows) | 572 tests: 564 passed, 8 failed |

失敗している 11 件は x86_64 と i686 で同一である (`chdir-*`、OLE 関係、
`hmac-sha2-test-case-3`、`octet-length-*` など)。アーキテクチャ固有の失敗は
残っていない。


既知の問題
----------

  * i686 の Clang ビルドには SEH の変換が無い。ハードウェア例外を
    `win32-exception` コンディションとして受け取る仕組みは `__try/__except` に
    依っているが、Clang は `i686-w64-mingw32` に対してそれをコンパイルできない
    (LLVM の 32bit x86 SEH は MSVC の例外テーブルを要求する)。そのため FFI の
    呼び先で落ちるとプロセスごと終わる。MSVC でビルドした 32bit 版と、
    llvm-mingw の x86_64 版には影響しない。テストは 3 件を i686 でだけ外して
    ある。

  * バイトコンパイル済みライブラリ (`*.lc`) はターゲット間で互換ではない。
    読み込み時にポインタ幅が決まるため、64bit ビルドが作った `.lc` を 32bit
    ビルドに読ませると FFI が壊れる。開発時は `tools/x bytecompile <arch>` を
    アーキごとに走らせる (`lisp/.bytecompile-arch` で食い違いを検出する)。

  * preview から引き継いでいる問題は 0.2.6.8-preview のリリースノートを参照。
