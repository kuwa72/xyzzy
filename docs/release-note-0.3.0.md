xyzzy リリースノート
====================

  * バージョン: 0.3.0
  * リリース日: 2026-08-21
  * ホームページ: <https://github.com/kuwa72/xyzzy>


このリリースについて
--------------------

バージョン体系を変えた最初のリリースである。中身は 0.2.6.8 と同じで、そちらの
リリースノートを参照。

  * [0.2.6.8 のリリースノート](release-note-0.2.6.8.md) — ターミナル (色、桁幅、
    Unicode、IME、リサイズ追従)、Nerd Font のアイコン、フォント設定の絞り込み、
    32bit の DLL 呼び出し、バイトコンパイルの取り残し、ビルドの整理


バージョン体系
--------------

`MAJOR.MINOR.PATCH` の 3 桁にした。

  * PATCH — バグ修正だけ (0.3.1, 0.3.2 …)
  * MINOR — 機能追加や作り直しが入ったとき (0.4.0)
  * MAJOR — 常用に耐えると判断したら 1.0.0

0.2.6.8 までは `0.{Y1}.{Y2}.{M}` (西暦下 2 桁と月) で、同じ月に 2 回出せない
体系だった。私家版でそれを守る理由も無いのでやめた。上流
([snmsts/xyzzy](https://github.com/snmsts/xyzzy) の 0.2.6.x) から分岐している
ことも番号で分かる。過去のタグはそのまま残してある。

あわせて、末尾が 0 の桁を落として `0.3.0` が "0.3" と名乗っていたのを直した。
ZIP とインストーラの名前は CMake の版番号をそのまま使うので、本体も 3 桁を出す。


開発
----

  * xyzzy Lisp の参照 skill (`.claude/skills/xyzzy-lisp`) を入れた。
    `reference/reference.xml` から `misc/gen-reference-skill.py` で作った 1837
    エントリの索引と、セクションごとの本文である。生成物と食い違わないよう、CI で
    `--check` を回している。配布物には入らない。
  * `main` が開発の本流になった。topic ブランチへの push では llvm-mingw の
    ワークフロー (5-7 分) だけが回り、MSVC の 3 アーキ (15-20 分) は統合先の
    ブランチ、PR、タグ、手動実行のときだけ動く。
  * `tools/x package` で、手元のクロスビルドから「そのまま動く一式」を作れる
    ようにした。Windows 機にコピーして確かめるまでを CI 抜きで回せる。


既知の問題
----------

0.2.6.8 から変わらない。

  * 32bit の llvm-mingw ビルドでは、FFI の呼び出しでハードウェア例外が起きた
    とき Lisp のコンディションにならずプロセスが落ちる。LLVM が 32bit x86 の
    SEH を扱えないためで、MSVC ビルドには影響しない。
  * ARM64 のバイナリを実際に動かす確認は MSVC のジョブ (windows-11-arm) だけで
    行っている。x86 の Wine では ARM64 の実行ファイルを起動できない。
